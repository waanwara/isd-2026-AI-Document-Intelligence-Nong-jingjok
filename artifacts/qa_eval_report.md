# รายงานผลทดสอบคำถาม 3 ระดับ — Jingjok-Thorius

ระบบยิงคำถามเข้า `POST /ask` โดยส่งเฉพาะ `question` + `program`
**ไม่มีการส่งเฉลยหรือคำอ้างอิงเข้าไปในระบบ/prompt** (บังคับด้วย assertion ใน `qa_eval.py`)

`auto` เป็นเพียงการคัดกรองเบื้องต้น (ตรวจว่าคำสำคัญปรากฏในคำตอบไหม)
คะแนนจริงตามใบเสนอโครงการต้องให้ **ผู้ตรวจกาช่อง** ว่าคำตอบถูก + อ้างอิงถูก

## การวัดผลสองมิติ

แยกวัดสองด้านเพื่อวินิจฉัยได้ว่าพลาดตรงไหน — กลไกดึงข้อมูลผิด หรือ LLM ตอบผิด

| มิติ | Text-to-SQL ทั่วไป | ระบบนี้ (RAG) วัดอะไรแทน |
|---|---|---|
| 1. กลไกทำงาน | SQL รันผ่าน | **Retrieval hit** — ดึงหน้าหลักฐานถูกไหม |
| 2. คำตอบถูก | ตรงเฉลย | **Answer accuracy** — auto-screen + ผู้ตรวจกา |

> ระบบนี้ไม่ได้ให้ LLM สร้าง SQL — เส้นทาง structured ใช้ SQL ที่เขียนตายตัว จึงรันผ่านเสมอ (100% ไม่มีความหมาย) จึงวัด **retrieval hit** แทน ซึ่งสะท้อนว่า กลไกค้นหลักฐานทำงานถูกจริงหรือไม่
